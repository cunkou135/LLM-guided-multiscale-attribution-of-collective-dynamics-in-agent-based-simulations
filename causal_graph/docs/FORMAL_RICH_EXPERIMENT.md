## 正式生成设置

新档案 configs/formal_rich.yaml 与 configs/deepseek_flash_formal.yaml 采用以下设置。它们用于扩大候选空间，不表示这一批输出已经完成正式论文实验验证。

|设置|本次值|含义|
|---|---:|---|
|宏观现象上限|8|覆盖有区别的现象，不能将同义表述拆分凑数|
|变量上限|72|允许每个现象、每个尺度多个互补变量，不固定各尺度数量|
|合并候选边上限|720|向上、向下、同层各最多 240 条；逐对检查合理机制，不要求达到密度目标|
|模型|deepseek-flash|沿用用户指定模型，档案中不含密钥|
|reasoning_effort|low|保留思考模式，实际推理用量见每次 usage|
|temperature|0.3|保留请求参数；供应商说明思考模式下该参数不生效，不能据此宣称控制了随机性|
|输出预算|196608 tokens|给较多定义、函数、推理及边理由留足空间；实际用量以传输记录为准|
|每次请求超时|1800 秒|各任务单独计时，非整个实验的总时限|
|传输重试|1|保留原始响应与错误，六类任务各自断点恢复|
|结构生成尝试|2|每批分别保留原始结果，失败不会标成成功|
|函数实现分批|每批 12 个变量|72 个变量对应 6 个代码请求，各批断点恢复；总任务类型仍为六类|
|JSON 输出|json_object|明确请求 JSON 模式；实测大批边仍出现无效 JSON，以本地严格解析和校验为准|
|边传输分批|每批预算至多 60 条，最多 4 批并行|来源变量互不重叠，每批可见全部目标变量，方向总预算不变|
|本地执行|trusted_reviewed|新函数逐份审查并批准精确 SHA-256 后才允许执行|

输出预算低于供应商当前公布的 384K 输出上限；可用模型与限额应按实际供应商档案确认。来源：[DeepSeek 官方模型说明](https://api-docs.deepseek.com/quick_start/pricing/)。预算是上限，不是强制输出量。参数行为见 [DeepSeek 官方接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)。

变量上限至少 48 时，使用单独标记的 broad-2 提示版本，要求尽量覆盖可观测的不同数学方面，保留实体/事件观测单位，避免同义变量、简单改单位及重复定义。小规模档案继续使用原来的逐字提示；有自动化回归核对原 Fish 公开实验的六份请求，旧缓存不被静默改写。

三类边仍分别独立判断；不使用参考因果图，不强制 DAG、树、同现象链、同尺度均衡或完全图，不新增显著性、时滞、干预或第二部分算法。没有机制依据的关系可以不生成，定义上的聚合关系不自动成为动态效应。模型可能输出少于上限的数量，这是允许的。

## 适合复杂图的绘制方式

本机已安装 Graphviz，未新增环境。默认 auto 优先使用其 dot 布局；没有 Graphviz 时仍可显式使用原 Matplotlib 后备路径。采用较紧凑的层间距和节点间距、14 点节点字、曲线自动布线及可区分的三种线型。节点 ID 在不同视图中保持一致，各视图单独安排位置以节省空白。

提供完整候选图、可执行图、三类方向分图、逐运行图；超过 12 个变量的图额外提供按现象的诱导子图和有向邻接矩阵。完整图保留全部关系，现象分图只显示内部关系，跨现象边在完整图、方向分图和矩阵中保留。矩阵行是原因端、列是结果端，每个有色单元对应一条实际候选边，可以完全避免箭头交叉。

几十个变量和数百条边的完整网络仍可能交叉，不承诺完全消除交叉，也不通过删边美化。论文正文建议用方向/现象分图说明具体结构，全图、矩阵、变量目录及完整理由放在补充材料。HTML 支持滚动、缩放、原始字号和点选节点突出相邻关系，不将大图强行缩小到窗口宽度。

```powershell
python -m causal_graph.visualize_graphs --experiment causal_graph/results/formal_rich_json_20261106/fish --experiment causal_graph/results/formal_rich_json_20261106/covasim --layout graphviz --output causal_graph/results/new_formal_views
```

Graphviz 视图导出 DOT、SVG、PNG、PDF；矩阵导出 SVG、PNG、PDF。输出清单保存每幅图对应的源文件哈希、全部节点/边 ID、过滤规则和绘图引擎；不会改写候选图。布局参数依据 [Graphviz 官方属性说明](https://graphviz.org/doc/info/attrs.html)。

## 检查器升级后的显式恢复

默认恢复仍要求源码一致。只有在明确升级检查器且核对来源后，才使用 `--resume-source-upgrade --generate-only --resume ...`，或在 run_formal 命令末尾增加 `--resume-source-upgrade`。输入、模型、生成上限、提示、Schema 仍必须完全一致；变化的源码及软件记录另存 generation_source_upgrade.json，原生成身份不会覆盖。

该模式可以重查缺少有效检查点的代码原始响应。重查前比对原请求与归档 SHA-256；原始响应和初次失败 validation.json 原样保留，复查结果写入单独 revalidation 文件，仍有签名、真实字段或其他错误时不批准为结构有效。所有批次的原始响应仍可逐一追溯。已经通过的代码不重写，也不调用模型重生成；缺失或仍无效的后续任务才继续实际模型请求。该模式仅用于生成恢复，不能据此执行未审查代码。


## 边分批与原始关系追溯

大规模边响应即使携带 response_format=json_object，实测仍有 JSON 语法错误，不能仅凭供应商的格式保证宣布通过。没有对错误 JSON 补键、补理由或补关系。当前丰富档案按每方向预算拆成 4 个来源变量分区，每区预算 60 条，最多 4 个请求并行；各分区的来源集合互不重叠，覆盖该方向全部可能来源，每批仍接收全部变量定义作为目标集合。三类方向仍独立，不接收其他批次或其他方向已生成的边。partition_plan.json 保存分区和预算，失败只重试对应批次。

原始边编号可能在同一响应或不同响应中重复。本地合并使用方向、分区和行号组成唯一 ID，原始编号、响应目录和行位置在 generation_sources 保留；不改变端点、方向、理由或关系类型。该编号规范只适用于明确分区且逐行保留来源的新传输路径；旧实验的原编号和严格规则不变。重复端点仍按原规则去重，全部重复来源保留。不接受缺少理由、错误方向、自环、不存在的变量或超出分区来源的边。

本地合并文件显式标注 deterministic_local_batch_assembly，不冒充模型原始返回。候选图中每条边、每个函数均指向真实模型响应；本轮没有提供参考图或人工添加机制。来源分区与配额会影响候选空间的采样方式，应在论文方法与实验配置中披露，不应说与整批采样完全相同。
